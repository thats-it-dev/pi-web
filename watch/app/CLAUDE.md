# pi-web watch app

Alloy watchapp (not a watchface): JavaScript runs on the watch via the Moddable SDK, UI is Piu via the pebble-ui library. Targets emery (Pebble Time 2) only.

- Watch code: `src/embeddedjs/` (ES modules; every module must be listed in `manifest.json`). Entry is `main.js`; screens are in `windows/`.
- UI is pebble-ui, the submodule `watch/pebble-ui`: run `git submodule update --init` before `pebble build`. See the `using-pebble-ui` skill.
- Phone code: `src/pkjs/` (plain ES5, CommonJS, `@rebble/clay`). Talks to the hub and relays over AppMessage.
- AppMessage keys are `pebble.messageKeys` in `package.json`; add new keys there first (a test checks `main.js` `KEYS` against them). The MSG/CMD protocol tables are in `../PROTOCOL.md`; the hub routes and frames in `../../docs/watch-api.md`.
- Settings (Clay): Hub URL and Dark theme.
- Shared modules live in `watch/shared/` (`js/` watch-side via manifest paths, `pkjs/` phone-side via relative `require`; `pkjs/package.json` marks it CommonJS for the tests).
- Tests: `node --test watch/app/test/` from the repo root (`npm run test:watch`).

Commands (run in `watch/app`, verified, see `../README.md`; no `--vnc` needed, the emulator runs headless):

    pebble build
    pebble install --emulator emery
    pebble install --emulator emery --logs   # console.log shows as xsHost.c lines
    pebble screenshot --no-open --emulator emery /tmp/emery.png
    pebble kill

Code size is memory in the emulator: the VM runs with `stack 6144, slot 45056, chunk 21504` (`src/c/mdbl.c`, mirrored in `manifest.json`; Home's menu is built during the slide transition, hence the stack). The mod archive (`build/mods/emery/mc.xsa`) is 40,259 B; the emulator ceiling is about 42,100 B with this stack (measured: 42,081 B launched, 42,133 B failed; failure is not monotonic above it), past which launch fails with `fxMapArchive failed`. Measure after any change with `bash ../pebble-ui/tools/sizes.sh .`; see `../README.md`. Watch-side state is applied in `onReadable` and the windows update in one deferred pass (`main.js`). Never make a new Style (or StatusBar) per update of a window that stays up: Piu keeps every Style a content has used until the next window slide, so take styles from `theme.js` `style()` and set strings in place (text.js `fill`). Dicts that land during a slide are held until it ends (`main.js` `receive`): parsing a home dict while Home slides in over the text window ran the heap out (Archive). See `../README.md`, "Styles stay in the chunk heap".

PKJS runs in the emulator on this machine with the Python 3.13 pebble-tool and the prebuilt aarch64 STPyV8 wheel (see `../README.md`, Toolchain); its logs are the `pkjs>` lines of `pebble install --emulator emery --logs`. Phone-side code is also covered by unit tests. A stand-in hub for the emulator: `node watch/app/dev/stub-hub.mjs --port 5173 [--scene default|all|empty|ring|many]` (`many`: twenty sessions, of which the phone sends twelve, its row limit, with long titles and replies; open sessions from it after changing Home or the text window, the chunk heap holds Home under them) from the repo root (`POST /stub/notice`, `/stub/query`, `/stub/dark`, `/stub/stream` to run the open session as the real hub does while pi runs, `/stub/ring` to route a ring note as the hub does; `POST /api/watch/new` adds an empty session). The phone doesn't relay streamed text: while a session runs the watch shows its last reply and an animated "…" (text.js `Dots`), and the phone sends the new reply from the history when the run ends (`../README.md`, "No live streaming"). The real hub's loopback internal API is `127.0.0.1:7879` (`internalPort`); `push` (boolean, default true) turns the hub's Web Push alerts on or off.

UI details (spec §8a): the header line is the label only (ellipsized, no time; the wire still carries `AT`); Home rows are one Port each, 56 px tall, Gothic 24 Bold title and 18 Bold status line, with a dot only for running and waiting sessions. The first row is "+ New session" (`home.js` `NEW`, id "+", never sent; not in `model.home`; the cursor stays on it across rebuilds): CMD `new` makes the phone POST `/api/watch/new` and open the empty session it gets, as a session alert's (`main.js` `sessionUntil`).

Launch (spec §8a; `main.js` `launch`, `bridge.js` `resume`): the watch sends CMD `launched` on every launch, `CODE` 0 when there is no alert's code. Priority: the code's target, then a pending query (opens on the first query dict, quiet for 10 s: `quietUntil`), then the session with the most recent activity, whatever its status (the phone opens it once it has a frame and the watch has reported Home, whose `showing` would otherwise close it, and only within 9 s of the launch, `RESUME_MS`; the reply opens it within `sessionUntil`, which a query or session screen clears: a query that pops up also cancels a session alert's launch), then Home. The session slides in once over Home; checked with scene `many`, no "memory full".

Ring notes with the app closed (spec §5; hub `index-webhook.ts`, `watch.ts` `appOpen`/`oldestDialog`): closed means no stream, poll or `showing` report for 45 s (the hub starts inside that grace); within it the note routes by the last-known `showing` as if open (a query that ended since is `gone`, never a new session), and with nothing connected an answer to the last-shown query, if the watch is still offered it, gets the closed path's receipt or miss alert. Closed, it answers only the oldest pi dialog that is select/confirm with options (never input/editor), was alerted, existed at `recordedAt` (+2 s; epoch ms, epoch seconds below 1e11, or a date string; no usable `recordedAt` → new session), and is not skipped or held back by an open web app; ring-profile queries never. A match sends one "Answered: <option>" receipt, a miss one "Didn't catch that" alert, both with the dialog's label; `gone` is silent. A re-upload is a 409: by `X-Index-Delivery`, or (the Index app sends none) by the content key `sha256(recordedAt, transcription, audio)`, which also names the stored files (`content-<hex>`). The stub's `/stub/ring` mirrors the grace and skips queries without options (it doesn't model `recordedAt` or alerts) and logs the alert lines.
