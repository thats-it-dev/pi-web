# Push alerts with an agent-written TL;DR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web Push becomes pi-web's only alert path. Every push carries a short title and a glanceable body; for a finished turn, both are written by the agent itself on its final `TL;DR [title]: …` line. A push is held back only while a visible PWA is on that same session.

**Architecture:**
- **TL;DR rule:** each headless pi spawn gets the rule through `--append-system-prompt`.
- **Parser:** a shared parser finds the TL;DR line. The hub uses it for push titles and bodies, and the PWA hides the line in the chat.
- **Notifier:** it becomes push-only. It handles turn outcomes (finished, needs_you, error), ring-profile queries and ring alerts. It holds back a push by per-session viewing, and owns a one-shot "still waiting" timer.
- **Viewing reports:** the PWA's existing visibility-gated events stream reports which session is on screen.
- **Removed:** the BlobDB notification path and its launch codes, hub and watch side.

**Tech Stack:** TypeScript on Node ≥ 22.18. The hub, shared and the watch use `node:test`; the app uses `vitest`. Pebble Alloy watch app (JS).

**Spec:** `docs/superpowers/specs/2026-10-28-push-tldr-design.md`

## Global Constraints

- Titles are at most **24 characters**. The event words are exactly `done`, `approve?`, `question`, `error`, `waiting`, joined to the project as `<project> · <event>` (U+00B7 with a space each side). The project is `basename(cwd)` cut so the whole title fits. Ring-profile queries use the project `ring`.
- Finished-turn title: the agent's `[title]` when present, cut to 24, else `<project> · done`.
- Bodies are clipped with the existing `clipText(s, 160)`. A push body is never empty: use the existing fallbacks and the service worker's stock text.
- TL;DR line form: the **last non-empty line** of the final assistant text, outside code fences, matching `TL;DR [<title>]: <summary>` or `TL;DR: <summary>`. Case-insensitive, and optional `**` bold around `TL;DR` is allowed.
- Suppression: a push for session S is held back only while some visible PWA client reports viewing S. Ring-profile queries (no session) are never held back.
- Stuck: **15 min** (`stuckMs = 900_000`), at most once per dialog or query. The body is `Still waiting: <original body>`, and nothing is sent if the item has resolved by then.
- Only headless (rpc) sessions push, as today. Watch API auth stays tailnet identity only.
- The watch app's behaviour is unchanged apart from removing notification-launch codes: plain launch still resumes the most recent session, and a pending query still opens first. Its built size must not grow.
- Commits: `git -c user.name="Michael Gutensohn" -c user.email="michael@gutensohn.me" commit`, message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. The model writes `TL;DR:` mid-reply, inside a code fence, or twice. Expected: only a last-line match outside fences counts, otherwise the fallback (Task 1 tests).
2. A long folder name (`ring-profile-experiments-2026`). Expected: the title is still ≤ 24 characters and ends with the event word (Task 5 `shortTitle` test).
3. Two clients: one visible on S, one hidden or on another session. Expected: S is suppressed and the others push; a disconnect stops counting (Task 4 tests).
4. A dialog answered in the PWA before 15 min. Expected: no "still waiting" push (Task 6 test).
5. A dialog pushed while the watch app is closed. Expected: it is marked alerted, so a ring note still answers it through the closed-app path (Task 5 test `needs_you push marks the dialog delivered`).

### Task 5: Push-only Notifier with short titles

**Files:**

  - `export interface NotifierDeps { enabled: boolean; push: (p: PushPayload) => Promise<boolean>; viewing: (sessionId: string) => boolean; markDelivered: (queryId: string) => void; isPending: (queryId: string) => boolean; stuckMs?: number; log?: (m: string) => void; setTimer?: (fn: () => void, ms: number) => unknown }`. `isPending`, `stuckMs` and `setTimer` are used by Task 6; add them now so the shape is final.

    `launchTarget`, `launchCodes`, the code table, `frame()`, `AlertMode` and `LaunchTarget` are removed.
- Push contents:

  | Source | title | body | kind |
  |---|---|---|---|
  | `turn`, finished | tldr.title cut to 24, else `shortTitle(p,"done")` | tldr.summary, else `clipText(stripTldr(o.text),160)` | `finished` |
  | `turn`, needs_you | `shortTitle(p, dialog is confirm ? "approve?" : "question")` | `dialogMessage(snap.dialogs[0])` clipped to 160 | `needs_you` |
  | `turn`, error | `shortTitle(p,"error")` | `clipText(o.text,160)` | `error` |
  | `query`, ring-profile only | `shortTitle("ring","question")` | `clipText(q.text,160)` | `query` |
  | `ringAlert` miss | `"Didn't catch that"` | as today | `query` |
  | `ringAlert` answered | `Answered: <option>` cut to 24 | as today | `query` |

  - `turn` returns early when `viewing(o.sessionId)`.

  - After a successful ring-profile query push, call `markDelivered(q.id)` as today.
- `watchPush(registry, onOutcome: (o: TurnOutcome, snap: Snapshot) => void)` loses its own viewer check and body building; it forwards the outcome. The `viewers?` parameter is removed, and suppression is the Notifier's job.
- `config.ts`:

  - `WATCH_ALERTS` is removed.
- `main.ts`:

  - `watchPush(registry, (o, snap) => void notifier.turn(o, snap))`.

### Task 6: "Still waiting" push

**Files:**
- Modify: `hub/src/notifier.ts`, `hub/src/watch.ts`
- Test: `hub/test/notifier.test.ts`, `hub/test/watch.test.ts`

**Interfaces:**
- Produces: `WatchService.isPending(queryId: string): boolean`. It is true when an external query with that id is unresolved (`queries.external()`), or when a live session currently has a dialog whose `dialogQueryId` equals it. Watch visibility, viewers and dismissals don't affect it.
- In Notifier, after a successful needs_you push or ring-profile query push, schedule one timer per query id (`setTimer ?? setTimeout`, with `.unref?.()`, `stuckMs ?? 900_000`). When it fires:
  - if `isPending(id)` is true, and the push wasn't suppressed (`viewing(sessionId)` for dialogs), push the same title with event `waiting` and body `Still waiting: <original body>`;
  - otherwise send nothing.
  - Never schedule twice for one id.

  - `watch.test.ts`: `isPending` is true for an open external query and false after `skip`. It is true for a live dialog even while a viewer holds the watch's dialogs back.
